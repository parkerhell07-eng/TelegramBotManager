# کلود آماده — سرور مشترک اپ (Ready Cloud Hub)

این پوشه سرویس «کلود آماده» اپ **مدیر ربات تلگرام** را دربر دارد: یک Worker مشترک که **یک‌بار** مستقر می‌شود و بعد از آن، **هر کسی که اپ را نصب کند** با یک ضربه و بدون ساخت حساب کلادفلر رباتش را ۲۴/۷ ابری می‌کند.

## چرا این سرویس وجود دارد؟

در حالت قبلی (v2.1.0) هر کاربر باید حساب کلادفلر می‌ساخت، توکن API می‌گرفت و اپ کد Worker را در حساب خودش آپلود می‌کرد. این برای کاربران عادی سد بزرگی بود. با «کلود آماده»:

- کاربر اپ: **فقط یک دکمه** — بدون ثبت‌نام، بدون توکن، بدون آپلود.
- صاحب اپ (شما): **یک‌بار** استقرار زیر، برای همیشه.

## استقرار یک‌باره (حدود ۵ دقیقه)

پیش‌نیاز: Node.js 18+ روی کامپیوتر.

```bash
cd cloud/hub

# ۱) ورود به کلادفلر (مرورگر باز می‌شود)
npx wrangler login

# ۲) ساخت فضای ذخیره‌سازی (KV)
npx wrangler kv namespace create HUB
#    خروجی چیزی شبیه این است:
#    id = "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
#    همین id را در wrangler.toml جای REPLACE_WITH_KV_NAMESPACE_ID بگذارید.

# ۳) کلید رمزنگاری توکن‌ها (یک رشته طولانی تصادفی؛ دوباره از آن استفاده نمی‌کنیم)
npx wrangler secret put HUB_KEY
#    مثلاً خروجی این دستور را بچسبانید:  openssl rand -hex 32

# ۴) استقرار
npx wrangler deploy
```

خروجی step 4 آدرس عمومی را نشان می‌دهد:

```
https://tbm-hub.<زیردامنه-شما>.workers.dev
```

## هم‌تراز‌کردن آدرس با اپ

اپ به‌طور پیش‌فرض به این آدرس وصل می‌شود:

```
https://tbm-hub.parkerhell07-eng.workers.dev
```

دو راه دارید (یکی کافی است):

1. **تغییر زیردامنه کلادفلر** به `parkerhell07-eng`:
   داشبورد کلادفلر ← Workers & Pages ← Subdomain ← تغییر به `parkerhell07-eng`.
2. **تغییر آدرس پیش‌فرض اپ** و انتشار نسخه جدید:
   ```bash
   ./gradlew assembleRelease -PhubUrl=https://tbm-hub.<زیردامنه-شما>.workers.dev
   ```
   یا مقدار `HUB_URL` در `app/build.gradle.kts` را ویرایش کنید.
   (در خود اپ هم بخش «ربات ابری ۲۴/۷ ← تغییر» آدرس را می‌توان برای دستگاه فعلی بازنویسی کرد.)

## تست سریع بعد از استقرار

```bash
curl https://tbm-hub.<زیردامنه-شما>.workers.dev/
# → {"ok":true,"service":"tbm-hub","ver":1}
```

سپس در اپ: داشبورد ربات ← «ربات ابری ۲۴/۷» ← گام ۱ (شناسه ادمین) ← دکمه «فعال‌سازی کلود آماده (یک ضربه)».

## چطور کار می‌کند؟

| مسیر | کار |
|------|-----|
| `POST /v1/register` | اپ توکن ربات + قوانین را می‌فرستد؛ سرور با `getMe` مالکیت را تأیید می‌کند، `route` و `secret` می‌سازد و توکن را **با AES-256-GCM رمزنگاری** در KV ذخیره می‌کند |
| `POST /hook/{route}` | تلگرام آپدیت‌ها را می‌فرستد؛ سرور با همان قوانین «پاسخگویی خودکار» جواب می‌دهد و هر پیام کاربر را به چت خصوصی ادمین کپی می‌کند؛ ریپلای ادمین روی نسخه کپی، به کاربر اصلی می‌رسد |
| `POST /v1/rules/{route}` | به‌روزرسانی قوانین بعد از ویرایش‌های اپ (بدون آپلود مجدد) |
| `POST /v1/unregister/{route}` | حذف کامل داده‌های ربات (توکن رمزنگاری‌شده + قوانین) |
| `GET /` | بررسی سلامت |

## امنیت و حریم خصوصی

- توکن ربات هرگز به‌صورت متن ساده ذخیره نمی‌شود (AES-256-GCM؛ کلید فقط در Secret ورکر).
- هیچ نقطه‌ای از API توکن را برنمی‌گرداند.
- هر وب‌هوک باید هدر مخفی `X-Telegram-Bot-Api-Secret-Token` را با secret اختصاصی همان ربات داشته باشد.
- ثبت‌نام: حداکثر ۳۰ ربات در روز از هر IP.
- مصرف منصفانه: سقف نرم ۲۰۰۰ پیام پاسخ‌گرفته در روز برای هر ربات؛ بعد از آن ادمین یک‌بار خبردار می‌شود و تا روز بعد (UTC) پیام‌ها بی‌پاسخ می‌مانند.
- با «خاموش‌کردن حالت ابری» در اپ، ربات کامل از سرور حذف می‌شود.
- اگر ترجیح می‌دهید داده‌ها فقط در حساب خودتان باشد، همان حالت پیشرفته قبلی (کلادفلر شخصی) سر جایش است.

## سهمیه رایگان کلادفلر (چرا کافی است؟)

Workers رایگان: ۱۰۰هزار درخواست در روز + Cron + KV (۱۰۰هزار خواندن/روز، ۱هزار نوشتن/روز). شمارنده مصرف به‌صورت نمونه‌برداری‌شده (هر ۲۵۰ پیام یک نوشتن) پیاده‌سازی شده تا در سقف نوشتن KV جا بماند. برای یک اپ با مصرف شخصی، ظرفیت چند صد ربات کم‌مصرف را می‌دهد. اگر روزی سهمیه تنگ شد: Worker با همان کد روی پولن ۵ دلاری بدون تغییر کد جا می‌گیرد.
